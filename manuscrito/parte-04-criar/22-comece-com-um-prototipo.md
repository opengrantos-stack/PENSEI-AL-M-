# CAPÍTULO 22 — COMECE COM UM PROTÓTIPO

## Você não precisa construir tudo para descobrir alguma coisa

Uma ideia pode parecer excelente enquanto está apenas na nossa cabeça.

Conseguimos imaginar o resultado.

Imaginamos pessoas usando.

Imaginamos o impacto.

Mas existe um problema:

**a nossa imaginação não consegue testar a realidade.**

Para descobrir se uma ideia funciona, precisamos transformá-la em alguma coisa que possa ser observada, experimentada e questionada.

É aí que entra o protótipo.

---

# O que é um protótipo?

Um protótipo é uma primeira representação de uma ideia.

Pode ser muito simples.

Pode ser:

- um desenho;
- uma página;
- uma maquete;
- uma apresentação;
- um formulário;
- uma pequena aplicação;
- uma demonstração;
- uma simulação.

O protótipo não precisa ser perfeito.

Ele precisa ser **suficiente para testar uma hipótese**.

---

# O protótipo não é o produto final

Esse ponto é fundamental.

Imagine que você queira criar um aplicativo.

O produto final pode ter:

- contas de usuários;
- pagamentos;
- notificações;
- banco de dados;
- segurança;
- painel administrativo;
- integração com outros serviços.

Mas o primeiro protótipo talvez precise apenas mostrar:

> “É assim que uma pessoa encontraria e utilizaria a solução.”

Não precisamos construir uma cidade inteira para testar uma rua.

---

# Comece pela hipótese

Antes de construir, escreva aquilo que você quer descobrir.

Por exemplo:

> “Acredito que pequenos produtores teriam interesse em publicar seus produtos em uma plataforma onde compradores possam encontrá-los.”

Isso é uma hipótese.

Agora podemos criar um protótipo que permita testar essa ideia.

Se ninguém demonstrar interesse, aprendemos alguma coisa.

Se houver interesse, também aprendemos.

O protótipo transforma uma opinião em uma pergunta que pode ser investigada.

---

# O protótipo deve responder a uma pergunta

Não comece com:

> “O que posso construir?”

Comece com:

> **“O que preciso descobrir?”**

Talvez você queira descobrir:

- se as pessoas entendem a proposta;
- se conseguem utilizar a interface;
- se a solução resolve um problema real;
- qual funcionalidade é mais importante;
- se alguém estaria disposto a utilizá-la;
- onde os usuários encontram dificuldades.

Cada pergunta pode exigir um protótipo diferente.

---

# Existem protótipos de diferentes níveis

Você pode começar com algo extremamente simples.

### Nível 1 — Ideia visual

Um desenho mostrando como funcionaria.

### Nível 2 — Fluxo

Uma sequência de telas ou etapas.

### Nível 3 — Protótipo interativo

A pessoa consegue clicar e experimentar.

### Nível 4 — Protótipo funcional

Algumas partes realmente funcionam.

### Nível 5 — Produto inicial

A solução já consegue atender usuários reais de forma mais completa.

Não precisamos começar no nível 5.

---

# Quanto menos você construir, mais rápido aprende

Imagine que você queira descobrir se uma determinada função é útil.

Você pode passar semanas desenvolvendo-a.

Depois descobrir que ninguém a utiliza.

Ou pode criar uma representação simples.

Mostrar.

Perguntar.

Observar.

Talvez descubra a resposta em pouco tempo.

Isso não significa que devemos sempre construir menos.

Significa que devemos construir **o suficiente para aprender**.

---

# O princípio da menor versão

Pergunte:

> **“Qual é a menor coisa que eu consigo criar para testar esta ideia?”**

Essa pergunta é poderosa.

Imagine:

> “Quero criar uma plataforma de cursos.”

A versão completa pode exigir:

- contas;
- pagamentos;
- vídeos;
- certificados;
- avaliações;
- painel administrativo.
